Chromium Digest: 2026-10-25

Overview

Analyzed 32 commits from Chromium main between 2026-10-25 (first: (c71b0c8), last: (231082c)). The majority were test re-enablements, field-trial configuration tweaks, and iOS/Android UI-metrics plumbing. No MAJOR breaking changes to stable embedder-facing public APIs were confirmed: the two candidates (WebAudioBus::ChannelData returning base::span and AudioBus sample-rate validation) are signature tightening / bug fixes with no removal of production-used APIs, and the Site Sharding work adds new opt-in embedder APIs without changing existing ones.

Blink & Web Platform

  • Paragraph boundary fix for ::first-letter. StartOfParagraphAlgorithm() and EndOfParagraphAlgorithm() now convert between DOM offsets and LayoutTextFragment indices instead of using the DOM offset directly as a fragment index. Previously a purely cosmetic ::first-letter style could move white-space-preserving paragraph boundaries (e.g. EndOfParagraph() before \n in "1ab\nde" returned 6 instead of 3). Materially affects editing/selection APIs and any embedder relying on paragraph units over fragmented text; the previously recorded expectation in endOfParagraphFirstLetterPre was itself wrong and has been corrected. (c71b0c8)
    BlinkHTML
  • Revert of deferred CalculationValue handle decrements. Reverts ecbab0a41 (~Length() decrements queued into a non-Oilpan vector) after it was linked to a crash (crbug/577331796). Restores immediate decrement of CalculationValueHandleMap entries from ~Length(); no API change, but relevant as a GC/crash-stability rollback in third_party/blink/renderer/platform/geometry. (600f90b)
    BlinkPerformance

Media & WebAudio

  • WebAudio decoding and WebAudioBus hardening. AudioBus::CreateBusFromInMemoryAudioFile() now honors the documented sample_rate == 0.0f contract (decode at the file's native rate) instead of dividing by zero in TryCreateBySampleRateConverting() and producing a 0-frame bus; invalid/negative target rates now return nullptr. WebAudioBus::ChannelData() was spanified to return base::span<float> (null private_ returns an empty span, invalid channel index is now a CHECK instead of DCHECK), and AudioDecoder/tests dropped their UNSAFE_TODO raw-pointer indexing. This is a signature tightening rather than a removal — see the final assessment; callsites must switch from float* to span. (d2aed4c)
    MediaBlinkAndroid
  • Remote Playback codec preconditions promoted from DCHECK to CHECK. MediaRouterUI and MediaRouteStarter now hard-CHECK that unknown video/audio codecs were already filtered by MediaNotificationService::ShouldInitializeWithRemotePlaybackSource(). Behavior change: an unfiltered codec is now a release-build crash instead of undefined behavior in debug builds only. (2144f13)
    MediaUI
  • Symphonia all-meta feature enabled. Container readers (MP3/ID3v2) now parse embedded metadata tags during probing/demuxing; symphonia-metadata v0.6 was already vendored, so only generated BUILD.gn feature flags changed. Affects media metadata availability for Chrome's Rust media stack. (592e07e)
    MediaBuild

Navigation, Security & Browser Lifecycle

  • Site Sharding added to content & Android WebView. New content::BrowserContext::SetSitesForEmbedderShard() (plus AwBrowserContext::SetSitesForEmbedderShard()) lets an embedder put a set of net::SchemefulSites into an SiteShard::kEmbedderSites shard so they never share a renderer with default-shard content, without full Site Isolation. SiteInfo::shard() participates in SiteInfo equality and ProcessLock comparison; BrowsingInstance now keeps one default SiteInstance per shard (replacing the single default_site_instance_); ProcessLock::SetIsUsed() assigns a process's shard once and CHECKs on any attempt to change it; RenderProcessHostImpl::IsSuitableHost() and the Citadel/CPSP checks reject cross-shard reuse. These are additive embedder APIs (nothing calls the WebView path yet) but the SiteInfo::Create()/BrowsingInstance shape and the CHECK semantics got stricter, so out-of-tree embedders subclassing or constructing SiteInfo/ProcessLock directly must update. (bfa7a4c)
    NavigationSecurityAndroid
  • Safe Browsing navigation checks prioritized. Behind safe_browsing::kPrioritizeSafeBrowsingNavigationCallbacks, synchronous hash-database lookups for non-prefetch navigations are posted onto BrowserTaskType::kNavigationNetworkResponse instead of the default UI queue, plumbed via UrlCheckerHolder::prioritize_navigation_callbacks and a new Client::GetCustomCallbackTaskRunner() on DatabaseManagerMechanism. Async checks, real-time checks, and prefetch stay on the default queue. Reduces navigation stalls under UI-thread congestion; Android's RemoteSafeBrowsingDatabaseManager is a follow-up. (112bbb5)
    SecurityNavigationPerformance
  • Faster renderer teardown on discard and on ChromeOS session exit. Stage 2 RenderFrameHostImpl::DiscardFrame() now passes ignore_workers=true to FastShutdownIfPossible(), matching DiscardedRFHProcessHelper; tests switched from IncrementWorkerRefCount() to IncrementPendingReuseRefCount(). Separately, ChromeOS ExitIgnoreUnloadHandlers() gained browser_shutdown::ShouldFastShutdownRenderers() (true for ShouldIgnoreUnloadHandlers() and ShutdownType::kBrowserExit), wiring skip-unload-handlers/ignore-workers/ignore-keep-alive/ignore-pending-reuse into OnShutdownStarting() and TabStripModel::CloseWebContentses(), plus disabling window hide animation in BrowserView::Close(). Behavioral note for embedders: on ChromeOS, service workers and keepalive fetches are terminated immediately at shutdown (session restore state is browser-side only). (2c4a157) (6ba4e77)
    BrowserChromeOSNavigation

Device & Platform APIs

  • SmartCardContext.release() IDL stub added behind a runtime feature. New release() method on SmartCardContext (plus a SmartCardContextRelease runtime-enabled feature and chrome://flags entry), gated by SmartCardContextRelease and instrumented with a use counter. The method currently always rejects with NotSupportedError — experimental, no compatibility impact yet. (bd0c800) (ce6c06c)
    BlinkSecurity
  • ENABLE_SMART_CARD migrated from a raw define to a buildflag. Moves to //third_party/blink/public:buildflags as BUILDFLAG(ENABLE_SMART_CARD); consumers (content/browser/devtools/render_frame_devtools_agent_host.cc, IWA entitlements browsertest, web_applications) migrated. Side effect worth noting: the old define only reached //content/browser, so smart-card entitlement assertions in isolated_web_app_entitlements_browsertest.cc were silently compiled out and are now active. Build-config change, not an API change. (c61e200)
    BuildBlinkSecurity
  • WebNN doc-only clarification. Comment added to execution_providers_info.h explaining why npu_concatenated_driver_version is intentionally excluded from operator|= merging (it is queried per-device by IsNpuDriverVersionBlocked()). No behavior change. (d2e2950)

Android & iOS UI, Metrics, and AI

  • Bottom Bar education gets UMA and stops colliding with the NTP theme tip. Adds Android.BottomBar.Education.Onboarding.{OnboardingType}.Event for the default/Gemini bubbles and opt-in dialog, and records Shown/Dismissed for tour tooltips into the existing Android.BottomBar.IPH.{IPHType}.Event histograms with a new TabSwitcher variant. BottomBarEducationCoordinator now sets a process-lifetime flag when education shows, and NewTabPageCoordinator defers (not drops) the NTP theme bottom sheet while it is set. (3b17e1f) (7d1956d)
    AndroidUIThemes
  • UmaSessionStats drops its Java-side native pointer. umaResumeSession and umaEndSession now route through static JNI entry points that call UmaSessionStats::GetInstance() (already a base::NoDestructor singleton); sNativeUmaSessionStats and init() are removed from UmaSessionStats.java, and UmaActivityObserverTest was updated accordingly. Public-Java-API removal, but confined to Chrome's own Android Java layer rather than a supported embedder API. (f9d8367)
    AndroidPerformance
  • iOS PageContext shadow-DOM text extraction made version-stable. getInnerTextIncludingShadowDom() now trims node.innerText before joining light-DOM and open-shadow-root chunks with a single \n, fixing the double/triple-newline discrepancy between iOS <27 and iOS 27 WebKit that broke PopulatePageContextWithShadowDom. The PageContextWrapperTest test was re-enabled. Production behavior change for the on-device page-context extraction used by iOS AI features. (5214418)
