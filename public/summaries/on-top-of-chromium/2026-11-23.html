Chromium Digest: 2026-11-23

Overview

On 2026-11-23 the main branch received 939 commits (705 relevant to embedders and platform developers), spanning the range from (1bd6be2) to (bf8bca4). The day was dominated by security and reliability hardening (libvpx VP9 overflow fix, libxml2/libxslt allocation checks, DevTools snapshot deserialization, OTR network isolation, credential-prompt privacy), by two genuine embedder-facing API breaks (CDP Target.createTarget scoping and the removal of RenderFrameHost::DocumentUsedWebOTP() plus its AutofillDriver virtual), and by a cluster of Windows/macOS windowing and toolbar fixes plus a Windows startup CPU-probe removal and an anti-aliasing revert that recovered a 14% FCP regression.

Breaking Changes & API Removals

  • ⚠️BREAKING: CDP Target.createTarget is now scoped to the session's BrowserContext. Non-Browser sessions reject browserContextId with InvalidParams ("browserContextId is only allowed for Browser target") instead of falling back to the last-used profile, and the target is resolved from DevToolsAgentHost::GetBrowserContext() (ServerError if unresolvable). The public content::TargetHandler constructor's DevToolsAgentHostClientChannel* parameter also lost its = nullptr default. Affects CDP drivers, DevTools frontends and chrome.debugger clients. (b2c9526)
    DevToolsBrowser
  • ⚠️BREAKING: content::RenderFrameHost::DocumentUsedWebOTP() is deleted outright with no deprecation shim, and the pure-virtual autofill::AutofillDriver::DocumentUsedWebOtp() is removed from the interface — any embedder with a custom AutofillDriver fails to compile. The flag now lives per-document in AutofillManager, surfaced through the new WebContentsObserver::OnDocumentUsedWebOtp(RenderFrameHost*), and is cleared in AutofillManager::Reset() rather than on RenderFrameHost navigation, so RFH-lifetime reset assumptions must be re-reviewed. (29ae0ec)
    AutofillBrowser
  • Long-deprecated page-load-metric observer APIs were removed: RenderFrame::SetLoadFromMemoryCacheCallback, RenderFrameObserver::DidLoadResourceFromMemoryCache(GURL, …), OnMainFrameRectangleChanged, OnMainFrameViewportRectangleChanged, DidObserveFirstScrollDelay, the matching WebLocalFrameClient virtuals, and WebLocalFrameObserver::OnMainFrameAdRectangleChanged. Replacements live on blink::WebLocalFrameMetricsObserver; out-of-tree code that overrides the old methods will fail to compile. (115880b)
    BlinkBrowser
  • Authenticated Proxy-auto-discovery proxies must now be HTTPS: non-HTTPS 407 challenges from PvD proxies are classified kNotApplicable (non_https_challenger), FetchProxyAuthCredentials() gained CHECK(proxy_server.is_https()), and PvD configs advertising google_chrome.auth over plain HTTP are rejected with the proxy IDs pruned from match rules (explicit DIRECT preserved). Enterprise deployments using plain-HTTP authenticated PvD proxies must change configuration; not flag-gated. (6af503b)

Networking & Storage

  • The HTTP cache now treats Vary: Authorization as Vary: *: HttpVaryData::Init()/MatchesRequest() route through HandleAsVaryStar() because authorization headers are not visible at the cache layer. Authenticated responses are therefore never reused from the cache and always revalidate over the network, including under LOAD_SKIP_CACHE_VALIDATION (new LoadSkipCacheValidationVaryAuth test expects 2 network transactions). Spec-correct (RFC 7234 §4.1) but a real change in request counts for authenticated resources. (7184423)
    NetworkStorage
  • WebRTC log-list handling is hardened and a shutdown hang is fixed: shared TextLogList::ReadLogListFile()/WriteLogListFile() open Log List with O_NOFOLLOW | O_NONBLOCK and require a regular file via fstat(), so a named pipe can no longer block open() forever on the background sequence and, with a running task, prevent the browser from exiting. Pipes/symlinks are replaced atomically, directories skipped, and a single 1 MB cap now applies in both callers. (8f1b619)
    WebRTCNetwork
  • SimpleCache enumeration no longer recurses once per failed entry: OpenNextEntry uses a single ref-counted completion callback instead of re-wrapping per retry, reducing completion stack depth from O(n) to O(1) and eliminating per-attempt allocations. A regression test drives 600 missing entries on a 128 KiB thread stack. (64d708e)
    NetworkStorage
