Chromium Digest: 2026-11-15

Overview

Analyzed 40 commits spanning refs/heads/main from (c416367) (first reviewed) through (f02b8ad) (last reviewed), with the range anchored by (8f11b54) and the head commit (c6cefae). The batch is dominated by networking work (proxy hardening, DNS/connection tuning defaults, QUIC IPv6-to-IPv4 migration plumbing), browser UI and extensions changes, and build-system maintenance. No confirmed MAJOR breaking changes to stable embedder-facing public APIs were found, though two items require downstream attention: a public Blink virtual renamed on WebLocalFrameClient/ChromeClient ((3992ada)) and upcoming GN enforcement of public_deps for generated headers ((9cc30ff)). Test-only, mechanical, localization, and non-Windows/macOS platform changes were largely filtered out.

Networking: Proxy & Connection Security

  • Proxy port restriction and HTTP/0.9 rejection are now enabled by default. Proxy endpoints are validated against IsPortAllowedForScheme() in HttpStreamFactory::Job::DoStart() (with defense-in-depth checks in HttpProxyConnectJob, the QUIC proxy job, and SocksConnectJob), failing with ERR_PROXY_CONNECTION_FAILED so normal proxy fallback applies. Statusless HTTP/0.9 and legacy Shoutcast ICY 200 responses relayed through a forward proxy are rejected with ERR_INVALID_HTTP_RESPONSE; HttpStreamParser gained an is_for_get_to_http_proxy parameter threaded through HttpBasicState and HttpProxyClientSocket. New public helpers net::IsProxyPortAllowed() and net::IsProxyChainPortAllowed() were added to net/base/port_util.h. Both behaviors are reversible via the kRestrictProxyPorts and kRejectHttp09FromHttpProxy killswitches. (2e584f2)
    NetworkSecurity
  • ReportingUploaderImpl hardened against re-entrant teardown. Pending uploads are now removed from the tracking map *before* requests are canceled or completion callbacks run during shutdown and destruction, preventing use-after-free when a callback re-enters the uploader. No public API change. (ab4625b)
    NetworkSecurity

Networking: Performance Defaults & QUIC

  • Optimistic DNS and IPv6 fallback tuning enabled by default on non-Cronet builds. Turns on kOptimisticDnsForTcp (use_stale_connectors=true), kEnableIntermediateDnsResults (SortTransactionsIndividually=true), kAdjustIPv6FallbackTime (100 ms) and kIPv6FallbackBasedOnRTT (1.1x RTT multiplier). Because AAAA results are sorted individually, the combined A+AAAA RFC 6724 sort is skipped and HostCache entries now consistently place IPv6 endpoints ahead of IPv4. MockHostResolverBase::ResolveFromIPLiteralOrCache now permits fresh cache hits under STALE_ALLOWED_WHILE_REFRESHING, matching HostResolverManager — embedder test harnesses relying on the old mock behavior will see differences. (827b566)
    NetworkPerformanceTesting
  • IPv6-to-IPv4 QUIC connection migration plumbing landed behind kEnableQuicV6ToV4Migration (disabled by default). Adds QuicMigrationAttemptContext and migration logic in QuicChromiumClientSession, with the fallback IPv4 address threaded from DNS resolution through QuicSessionAttempt, QuicSessionPool::DirectJob, AsyncDnsJob and EndpointConnector. The address is currently approximated from the original A-record pending a real alternative-server-address spec, so expect interface churn in follow-ups; new migration histograms were added. (b5a6ded) (1276855) (b6987ca)
    NetworkPerformance
  • Updater's libcurl network fetcher extracted into its own files and hardened. Pure move out of network_fetcher_linux.cc into chrome/updater/net/network_fetcher_libcurl.{h,cc}, then extended with an optional explicit proxy (overrides proxy env, keeps CONNECT reply out of the header callback), redirect following (max 5) reporting the final status, response codes emitted for bodiless/chunked/redirect responses, cancellation via net::ERR_ABORTED per the components/update_client/network.h contract, and CURLOPT_NOSIGNAL plus connect/low-speed timeouts. macOS adoption as an alternative to NSURLSession for explicitly proxied downloads is planned. (b3429ca) (315f6ad)
