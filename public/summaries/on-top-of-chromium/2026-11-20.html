Overview

On 2026-11-20 the main branch received **1,123 commits**, of which **837** were filtered as relevant to browser-layer, networking, extensions, security, performance and build work. Range: (08a1fa1) → (44c1bcd).

Breaking API Changes

  • ⚠️ContentBrowserClient::WillInterceptWebSocket() changes from (RenderFrameHost*) to (RenderFrameHost*, BrowserContext*); the context is derived from the initiator's RenderProcessHost and is documented as never null, so embedders can enforce per-context policy for service-worker and shared-worker connections where frame is null. The in-tree change is behavior-neutral, but every out-of-tree override must be updated and recompiled. (9f0499b)
    NetworkBrowser
  • ⚠️WebContentsDelegate::ShowRepostFormWarningDialog() and NavigationControllerDelegate::ActivateAndShowRepostFormWarningDialog() now return bool instead of void. Returning false (the default, "embedder cannot show the dialog") cancels the pending reload, so Headless Chrome and content_shell get an error instead of hanging — update all overrides. Paired with an opt-in, default-off checkForRepost parameter on DevTools Page.reload. (0df9dbc)
    NavigationBrowser
  • ⚠️The pure-virtual BrowserWindow::GetExclusiveAccessContext() is removed from chrome/browser/ui/browser_window.h. Migrate to ExclusiveAccessManager::From(browser)->context() or the extracted BrowserViewExclusiveAccessContext::From(browser); context ownership moves to BrowserWindowFeatures and the type splits into its own GN target (//chrome/browser/ui/exclusive_access:browser_view_exclusive_access_context). ~41 in-tree files updated, all downstream consumers break. (25174f9)
    UIBrowser
  • ⚠️Extensions feature registration rework with no deprecation window: ExtensionsAPIProvider's pure-virtual Add*Features(FeatureProvider*) methods become const Get*Features() returning extensions::StaticFeatureTable; FeatureProvider::GetAllFeatures() returns a FeatureSpan (std::vector<const Feature*>) instead of the name-keyed FeatureMap; FeatureProvider is now final with a non-virtual destructor; the json_features GN method_name convention flips Add* → Get*. Motive was allocation/perf only (Win x64 Release: 18 → 4 startup allocations, ~12.4 KB → 4.1 KB retained, ~42 → ~14 µs warm construction). (7481681)

Security & Networking

  • Dedicated workers whose script response carries a CSP sandbox directive without allow-same-origin now get an opaque StorageKey with cross-site ancestor-chain semantics, and inherited Storage Access API status is cleared on both browser and renderer paths — closing a first-party cookie/authority leak through WebSocket handshakes, subresource fetches and worker-bound Mojo. Adds content::DeriveOpaqueStorageKey(); OnScriptLoadStarted() and blink::WebDedicatedWorker gain an updated_origin parameter. Kill switch CSPSandboxedWorkerOpaqueOrigin (default on). (adc26fc)
    SecurityStorage
  • ServiceWorker race-network-and-fetch-handler no longer re-dispatches post-fallback redirects as a fresh FetchEvent, which previously exposed post-redirect cross-origin URLs and credentialed redirect parameters to the worker via event.request.url. Also fixes a CorsURLLoader state-machine bypass that dropped opaque response tainting on cross-origin→same-origin redirects in no-cors mode, implemented by reclaiming the in-flight URLLoader with TakeURLLoader() and forwarding FollowRedirect() on the existing pipe. (8f1eee4)

    WebRTCSecurity

Browser Behavior & UI

  • --app=<url> now resolves against installed web apps on desktop: a URL in the scope of an installed, OS-integrated web app launches that app's window instead of a URL-derived app window, so window identity changes from chrome-<host>__<path>-Default to the app's (taskbar/dock grouping and OS integration now apply). Startup becomes asynchronous when the web-app registry isn't loaded yet (mirroring --app-id), with a synchronous plain-window fallback when nothing matches — review deployment scripts relying on per-URL window identity. (255d9e9)
    Browser
  • Window placement and session commands now persist at logout/shutdown: chrome::SessionEnding() previously terminated the process without closing windows, and SessionService commands waited on a 2.5 s timer that never fired. Placement is now saved least→most recently active (most-recent window wins the "new window" pref) and BrowserProcessImpl::EndSession() flushes pending SessionService/AppSessionService commands with SaveNow(), so recent moves and session edits survive WM_ENDSESSION and SIGTERM.
