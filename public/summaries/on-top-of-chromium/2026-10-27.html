Chromium Digest: 2026-10-27

Overview

On 2026-10-27, 1,197 commits landed on Chromium main, of which 970 were classified as relevant to embedders. Highlights include several embedder-facing breaking API changes (ContentBrowserClient::GetApplicationLocale(), SyncClient, WebWidget screen info, Blink snapshot Mojo tokens, the network isolation partition enum, and headless SwiftShader defaults), plus security hardening, networking behavior changes, and measurable performance wins. First commit: (99491af); last commit: (128ca60).

Breaking API Changes

  • ⚠️ContentBrowserClient::GetApplicationLocale() now returns base::i18n::LanguageTag instead of std::string. Every override (Chrome, Android WebView, Cast, Headless, WebEngine, TestContentBrowserClient) must be updated, and callers must stringify via tag_string(). In-tree overrides and --lang/accept_language call sites were updated in the same CL, but downstream embedders need a rebuild and source changes. (bed7077)
    BrowserBase
  • ⚠️components/sync/service/sync_client.h gains a pure virtual SyncClient::ArePasskeysLocked(), and SyncService::UserActionableError gains desktop-only kPasskeysLocked plus a PasskeysLockedChanged() notifier. Embedders implementing SyncClient must add an override, and exhaustive switch statements over UserActionableError (sync UI, app menu, profile menu, password store) need new cases. (f75b354)
    SyncProfilesUI
  • ⚠️WebWidget::GetScreenInfo(), GetScreenInfos(), GetOriginalScreenInfo() and GetOriginalScreenInfos() were removed from the public Blink embedder header web_widget.h. Screen-info getters move to WebFrameWidget, and ChromeClient::GetOriginalScreenInfo() is replaced by GetOriginalDeviceScaleFactor(). Custom plugin/host widgets implementing or calling these must migrate and recompile. (aab8e04)
    BlinkUI
  • ⚠️Blink snapshot permissions were reworked: blink::mojom::ReceivedSnapshotListener is deleted, FileSystemManager::CreateSnapshotFile() now returns pending_remote<SnapshotPermissionToken>, and FileBackedBlobFactory::RegisterBlob() loses [Sync] and replaces block_on_registration with the token. Components implementing or calling these interfaces must be updated; the rework also fixes a registration race that could outlive the permission grant. (05d7b1a)
    StorageSecurity
  • ⚠️NetworkIsolationPartition::kProtectedAudienceSellerWorklet (id 1) was removed from the exported enum, and NetworkIsolationPartitionFromInt() now backs IsolationInfo::Deserialize() / NetworkAnonymizationKey::FromValue(), which reject persisted entries using the obsolete value instead of restoring them. Embedder switches over the enum break, and cached isolation data containing partition 1 is silently dropped. (2b56d0b)
    NetworkPrivacy
  • ⚠️Headless now disables the GPU by default: --headless / --headless=new pass --disable-gpu unless --enable-unsafe-swiftshader is supplied, so WebGL and WebGPU contexts return null in automation that relied on the implicit SwiftShader fallback. Update headless command lines or explicitly opt in (--enable-unsafe-swiftshader, plus --enable-unsafe-webgpu for WebGPU). (b60b30b)
    GPUWebGLWebGPU
  • ⚠️Smaller but genuine source-compatibility breaks: gfx::GetFallbackFont() now takes base::i18n::LanguageTag instead of std::string; ColorProviderUtilsCallbacks::ColorIdName() was removed from the exported ui/color/color_provider_utils.h (names now come from CSS tables); and base::Feature::default_state became the private default_state_ (use GetDefaultState()). Compile-time only, no behavior change. (7bb2a7b) (6abf312) (b9920b3)
    BaseUIFonts

Security & Privacy

  • macOS GPU process sandbox: kMacSandboxRestrictGpuDarwinUserDirs and the restrict-gpu-darwin-user-dirs sandbox parameter are removed, making Darwin user-directory and shader-cache restrictions unconditional. There is no killswitch left for embedders to disable this hardening. (794d841)
    SecuritymacOSGPU
  • Middle-click paste-and-navigate is now restricted to HTTP(S): NewTabFromClipboardURL and ExecutePasteAndGo use SchemeIsHTTPOrHTTPS() instead of IsWebSafeScheme(), so blob:, data:, file:, extension: and ws: clipboard URLs are no longer auto-opened. Behavior hardening with no API change. (eb5c738)
    SecurityNavigation
  • Hardening cluster: NTP custom background uploads now read once and write atomically via ImportantFileWriter (closing a symlink-following attack); ui_devtools enforces strict Host/Origin checks and GetSourceCode path containment; Rust Mojo runs the C++ header validator on incoming messages before C++ consumers see them; and usb-storage (0x08/0x06/0x50) was added to UsbInterfaceDetachAllowlist only for unrestricted_only callers, preserving WebUSB blocking. (ff485c3) (8020a69) (0dfbc9e) (1c9ae32)
    SecurityPrivacyUSB

Networking

  • New default-on net::kClearAuthControllersOnProxyChange (enterprise-disablable): HttpNetworkTransaction discards proxy auth controllers and non-cryptographic server auth state when the proxy chain changes mid-auth, tracks handled challenges, and fails with ERR_TOO_MANY_RETRIES after four proxy changes. Relevant to embedders using dynamic/PAC proxy configurations. (bedd93b)
    Network
  • Networking robustness: the Quiche roll hardens connection handling (connection ID rotation, min(1ms, SmoothedRTT) delayed-ACK floor, structured-headers bounds checks, ~920 bytes smaller TLS server params), and HostResolverCache::RestoreFromValue() now skips only the entry whose NAK fails to parse instead of discarding the whole persisted DNS cache. (789413b) (b805cf3)

Browser & UI Behavior

  • Web app same-app context-menu "open in new window" now passes WindowOpenDisposition::kNewWindow (previously kCurrentTab), and WebAppLaunchProcess::MaybeFindBrowserForLaunch() no longer reuses the current window for that disposition; single-window/prevent-close enforcement is centralized. Web App launch handlers (focus-existing / navigate-existing) should account for the new window. (b921d08)
    BrowserUI
  • Tab strip interaction fixes: middle/tertiary-button tab close no longer resizes the strip until the pointer exits; tab-group underline now animates correctly through collapse; and dragging a collapsed group header no longer selects or activates invisible member tabs, with thumbnail lookup targeting the dragged group's active tab. (71d578a) (2a631ea) (1304cb4)
    TabsUI
  • WebUI omnibox popup fixes: the searchbox now scrolls itself to start on focus loss instead of relying on a Blink blur (which never fires without page system focus), and Stage-4 Escape unconditionally reverts the edit model so a stale native selection range is not re-applied when the popup reopens. (4e78814) (266202f)
    UIBrowser
  • Enterprise/security reporting now uploads on profile open: default-enabled kUploadReportOnProfileOpen replaces the previous 24-hour wait timer (validated at 50% Stable). An observable default-behavior change for enterprise-deployed embedders and their reporting infrastructure. (e7323a2)
    EnterprisePolicy
  • Browser-verified user activation lands behind blink::features::kTrustedUserActivationTriggers: RenderWidgetHostImpl counts expected activation notifications on mouse/key down with a 30s expiry, and FrameTreeNode::VerifyUserActivation() rejects unverified renderer notifications. Extensions

  • The new chrome.runtime.getDocumentId() extension API is relanded (flag-guarded by kApiRuntimeGetDocumentId): synchronous document-ID lookup from a WindowProxy or frame-owner element, backed by RenderFrameHost::GetDocumentToken() and a new blink::WebFrame::FromWindow(). Additive but useful for extension messaging targets; out-of-process frames are unsupported. (23d5301)
    Extensions
  • Extension robustness: chrome.windows.update(), windows.create() and tabs.create() are hardened against use-after-free when nested message loops destroy the Browser/BrowserView during fullscreen transitions (WindowController::GetWeakPtr() plus liveness checks), and <webview> guests serving webview-accessible chrome-extension:// resources no longer trigger false-positive renderer kills on runtime.sendMessage/connect (ProcessMap::IsWebViewProcessForExtension()). (1b90fe7) (2e15794)
