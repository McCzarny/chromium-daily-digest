Chromium Digest: 2026-11-22

Overview

This batch spans 38 commits (first: (86ae675), last: (bbbfd3d)). Twenty were retained for Windows/macOS embedders (chrome/browser, ui, and testing utilities); the rest are Linux/X11/GTK, Android, iOS, ChromeOS, translation dumps, and flake markings that are out of scope. No commit in this batch is a confirmed breaking change to a stable, embedder-facing public API: the two removal candidates — Blink's test-only WebElement::ShadowRoot() and the already-defaulted MetricsServiceClient::GetProfileCountryIdForPrivateMetricsReporting() hook — have no production embedder dependencies.

Security & Privacy

  • Credential leakage in bug-report logs fixed. CalculateKeyValue was printing raw Google API keys and OAuth client secrets at VLOG(1) for values sourced from environment variables, GAIA config, CLI switches, and default_if_unset — a real exposure since --enable-logging --v=1 is routine in attached logs. The three runtime overrides now emit a redacted preview via RedactKeyValue() (prefix/suffix plus length for ≥16 printable ASCII chars, [empty]/[redacted, len=N] otherwise) while default_if_unset omits the value entirely; redaction still distinguishes overrides for developers. (79f27fe)
    SecurityPrivacy
  • Autofill stops leaking across V8 worlds through closed shadow roots. form_autofill_util.cc now filters closed-shadow-hidden DOM elements out of AutofillEvents, enforcing Shadow DOM encapsulation so element handles and autofilled values cannot cross world boundaries. A companion Blink cleanup collapses the duplicate WebElement::ShadowRoot() into OpenOrClosedShadowRoot() (now const); the removed accessor was used only by in-tree tests and the replacement is semantically equivalent for non-null elements, so third-party callers need at most a one-line change. (2aca3e5) (198d512)
    AutofillBlinkSecurity
  • Windows clipboard no longer CHECK-fails on malformed drag streams. A drag source can advertise TYMED_ISTREAM without an actual IStream*, previously tripping a CHECK in clipboard_util_win.cc when Chrome read file contents. The missing stream is now treated as a failed read with the medium marked TYMED_NULL before release; filename handling and valid-stream paths are unchanged (fixes 583454016). (a6d88ab)
    WindowsUISecurity

Browser UI (Windows/macOS)

  • WebUI toolbar now matches Views for back/forward mouse buttons. These buttons were reaching toolbar WebUI buttons as ordinary clicks, triggering reloads or inverted navigation. webui_toolbar_web_view.cc intercepts them in PreHandleMouseEvent() so they never reach the page, and on Windows forwards the matching APPCOMMAND to ExecuteWindowsCommand() — reproducing Views behavior where the unhandled event becomes WM_APPCOMMAND and navigates the active tab. On macOS the buttons now do nothing, also matching Views; the toolbar still takes focus on these clicks (crbug.com/519327032). (c16e2cb)
    UIBrowserWindows
  • All page actions now carry a unique element_identifier; the location-bar anchoring fallback is gone. Page actions without an identifier were never registered with ElementTracker, so CreateAndShowAnchoredMessage() anchored to kLocationBarElementId instead of the icon — unlike Views PageActionView. Identifiers were added for Lens overlay, Glic contextual cueing, anchored contextual cue, and the debug fake action; uniqueness is now compile-time enforced and the null filtering in GetAllElementIdentifiers() was removed. Anchored IPH/bubble placement for these actions visibly moves from the omnibox to the respective icon. (464d953)
    UIBrowser
  • Full WebUI omnibox popup can be shared across a profile's windows (flag-gated). Under OmniboxWebUIPopupShareAcrossWindows, OmniboxPopupFullPresenter joins a shared pool, skips its constructor-time load when another window holds a full popup, and adopts an idle one on show or window activation; because the popup only displays once its page is ready, Show() cannot create it and the presenter instead requests one from OmniboxPopupWebUIPoolClient, waiting while a peer's popup loads and creating its own only when the shared popup is busy or closed. Only the last-activated window claims a shared ready popup, and "idle" excludes drafts, pending ClearPopup() replies, and pending context-menu requests. kWebUISearchboxWithoutModelController keeps per-window behavior. (4dd6eb7)
    BrowserUI
  • Content-area layout skips redundant work during animations. ContentsContainerView and ContentsContainerOutline avoid needless mini-toolbar and outline updates during layout, targeting smoother side-panel and vertical-tabs transitions (Bug 501743908). (0ace792)
    UIPerformance

Performance

  • Menu hit-testing and tooltip lookup now binary-search instead of scanning every item. SubmenuView previously ran the default linear child scan for event targeting on every pointer move, even though Layout() already stacks visible children top to bottom. Layout() now caches visible children and TargetForRect() (via a ViewTargeter) plus GetTooltipHandlerForPoint() binary-search that cache by y; the cache is invalidated on child add/remove/show/hide and left empty — falling back to base implementations — when a child has a layer or its own targeter. Measured on a 900-item bookmarks-bar overflow menu: UI-thread CPU for a pointer sweep drops 440 ms → 140 ms and hover-highlight lag drops 462 px → 78 px. Internal, but a large responsiveness win for large menus on every platform. (86ae675)
    UIPerformance

Bug Fixes & Stability

  • Glic no longer holds a dangling BrowserWindowInterface. GlicWebClientHandler keeps GlicToolsHolder alive across browser-window lifetimes (notably when Glic is detached into a floating window), but CreateAiOverlayToolsForGlic resolved the active browser once at Mojo pipe creation and stored a raw_ptr<BrowserWindowInterface> on AiOverlayTools — a MiraclePtr dangling-pointer crash whenever that initial window closed while Glic stayed open. A BrowserResolver overload on AiOverlayTools::Create() (plus RegisterBrowserDidClose() subscription for fixed-browser callers) now resolves the most recently activated normal browser window per tool call. (fc72ab7)
    AIBrowser
  • WebAudio stops re-querying a failed output device and now surfaces the failure. On authorization failure or timeout during RendererWebAudioDeviceImpl construction, HandleDeviceStatus() called Stop() and cleared sink_, so the next MaybeCreateSinkAndGetStatus() recreated the sink and issued a second blocking GetOutputDeviceInfo() on the main thread. The status is cached in sink_status_ and returned without recreation (a stopped working device keeps OK so it can reopen; Start() still reopens asynchronously and failures surface via OnRenderError()). Consequently AudioContext({sinkId}) and setSinkId() report the initial error instead of silently retrying against placeholder params, and WebAudio.AudioDestination.OutputDeviceStatus records the cached value. (f69fee8)
    Media
  • Autofill field-type inference moved to LanguageTag. determine_possible_field_types.cc and its vote-upload path now consume LanguageTag rather than raw locale strings, aligning inference with the rest of the autofill language pipeline (Bug 40100455). Internal behavior only; no public API or feature-flag surface changed. (1dee991)
    Autofill

Embedder API Surface

  • Private-metrics country hook removed from MetricsServiceClient (not breaking). PUMA was discontinued and PumaService deleted, so GetProfileCountryIdForPrivateMetricsReporting(), CountryAccessReason::kPrivateUserMetricsReporting, the PumaService friend declaration in CountryAccessKey, and ChromeMetricsServiceClient::cached_profile_ (plus the now-unneeded regional_capabilities includes) were removed. This is a genuine removal rather than a deprecation, but the base class supplied a non-pure default returning std::nullopt, so no embedder was required to override it — it is marked non-breaking because no production code path depended on the hook after PUMA shutdown. (345928a)

Testing & Developer Infrastructure

  • Public Transit conditions now evaluate live active Stations. ActivityExistsInNewTaskCondition previously snapshotted the active Stations' task ids in its constructor; it now re-checks on every evaluation, skipping the owning Station (which only becomes active after its Transition completes). This removes the TripBuilder.complete() workaround of calling requireToBeInNewTask() right before the Trigger runs, unblocking reusable end-state descriptions for Transition v3. Because the live check now sees Stations created inside a Trigger, TabStripDragDropTestBase starts its second window directly instead of via MultiWindowTestHelper.createNewChromeTabbedActivity(); six other test classes migrated from ChromeTabUtils#newTabFromMenu() to CtaPageStation#openNewTabFast(), several of them already @DisabledTest. (a76a871) (e298d6d)

Separately, SettingsTest.GeicSubpage now uses TestPrefsBrowserProxy and resets PrefService, eliminating a race where an async onPrefsChanged(false) from SettingsPrivateEventRouter overwrote a just-clicked toggle value.
