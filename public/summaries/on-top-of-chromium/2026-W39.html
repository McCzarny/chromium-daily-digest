Chromium Weekly: 2026 Week 39

Overview

During week 39 of 2026, Chromium development saw major security hardening, public API breaking changes, and internal refactoring across browser UI, networking, and extensions. Highlights include stricter permission flows, signature verification updates, and architectural cleanups in desktop embedding targets. This summary covers 3 relevant commits out of 4,375 total across 6 days.

Breaking Changes & API Updates

  • ⚠️BREAKING CHANGE The public content::ClipboardEndpoint constructors were privatized; embedders must migrate to ClipboardEndpoint::ForUnloadedTab() and ClipboardEndpoint::ForFrame() static factories. (23ddcb7)
    Browser
  • ⚠️BREAKING CHANGE Removed GLES2Interface::DidGpuSwitch() from the GPU command buffer client interface, impacting embedders implementing custom GLES2Interface subclasses. (17a3918)
    GPUCompositor
  • ⚠️BREAKING CHANGE network::mojom::NetworkContext::CreateWebSocket gained a required target_network parameter, requiring updates in embedder TestNetworkContext overrides. (7b61681)
    Network
  • ⚠️BREAKING CHANGE Removed crypto::SignatureVerifier entirely from //crypto; embedders must migrate to crypto::sign::Verify/Verifier and crypto::keypair::PublicKey. (d19202f)
    CryptoSSL

Security & Privacy Hardening

  • Modal dialog blocking now prevents tabs from entering or re-entering HTML fullscreen via BrowserWindowModalDialogDelegate::SetWebContentsBlocked(), enhancing stability and hardening stable fullscreen handling on Windows/macOS. (9dcb787)
    SecurityUIWindowsmacOS
  • SRI message signatures (Ed25519) are now strictly enforced for Service Worker-synthesized responses, preventing bypasses where forged signatures skipped network-service validation. (b47df21)
    SecurityServiceWorkerNetwork
  • Form-control popup widgets (select, color pickers, showPicker()) now require and consume transient user activation in the browser process to protect against compromised renderers. (a64fc96)
    SecurityUI

Browser Architecture & UI

  • ⚠️BREAKING CHANGE Split browser_view.h out of the //chrome/browser/ui:ui monolith into its own GN target (browser_view_header), fixing circular dependencies. Embedders relying on browser_view.h as an umbrella header may require explicit includes. (321684d)
    BrowserUIBuild
  • ⚠️BREAKING CHANGE Public FindBarController accessors were removed from BrowserWindowFeatures; embedders must migrate to FindBarController::From(BrowserWindowInterface*) which uses UnownedUserData. (6126eaa) (99f9595)
    BrowserUI
  • Vertical tabs rail is now user-resizable with manual width persistence, and tab focus mode reliably dissolves temporary groups on unfocus. (93111e4)
    TabsUIBrowser
