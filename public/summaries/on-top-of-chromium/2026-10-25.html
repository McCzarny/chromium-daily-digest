Chromium Digest: 2026-10-25

Overview

This digest covers 27 commits between (c71b0c8) and (231082c) (~main@{#(1726678)} .. main@{#(1726572)}). The majority were iOS/Android-only test re-enables, field-trial config edits, and mechanical refactors outside the scope of desktop (Windows/macOS) embedders. After filtering, the notable changes concern Safe Browsing navigation-priority plumbing, new content-layer site sharding support, WebAudio/media fixes, discard-driven fast shutdown, Autofill IBAN regex patterns, an experimental Smart Card API addition, and test-infrastructure tuning. No confirmed MAJOR breaking changes to stable public APIs were found; the WebAudioBus::ChannelData spanification is a source-level type change for a Blink public header but falls under the span-migration guidance and is not treated as breaking here.

Security & Navigation

  • Safe Browsing check replies for synchronous, non-prefetch navigation hash-database lookups can now be posted on BrowserTaskType::kNavigationNetworkResponse instead of the congested default UI queue, so navigations deferred in WillProcessResponse waiting on sync_sb_checker_ are no longer starved. Plumbed via Client::GetCustomCallbackTaskRunner() through DatabaseManagerMechanism into SBDatabase::GetStoresMatchingFullHash; async checks, real-time checks, and prefetch requests stay on the default queue. Gated behind safe_browsing::kPrioritizeSafeBrowsingNavigationCallbacks; Android's remote database manager follows separately. (112bbb5)
    SecurityNetworkPerformance
  • Site scoping change for error pages when shards are configured: with shards enabled, error pages for blocked renderer-initiated requests commit in the destination's process (NavigationRequest::ComputeErrorPageProcess()) rather than the current one, so a process never hosts content from another shard. Default configuration (no shards) is unchanged. (bfa7a4c)
    NavigationSecurityBrowser

Content API & Multi-Process Architecture

  • New embedder-facing sharding support for default SiteInstances (WebView Site Sharding): adds SiteShard (kDefault, kEmbedderSites), BrowserContext::SetSitesForEmbedderShard() (call-once, HTTP(S)-only, CHECK-guarded against default SiteInstanceGroups / single-process / Rust CPSP), SiteInfo::shard() folded into SiteInfo equality and ProcessLock comparison, one default SiteInstance per shard per BrowsingInstance, and ProcessLock::SetIsUsed() shard pinning. RenderProcessHostImpl::IsSuitableHost() and Citadel checks prevent cross-shard process reuse. Purely additive for embedders that never call the new API (shard computation is skipped when no shards exist), but it touches core SiteInfo/ProcessLock construction signatures — embedders constructing SiteInfo by hand must add the shard argument. (bfa7a4c)
    NavigationSecurityBrowser

Media & Web Audio

  • WebAudio native-sample-rate fix: AudioBus::CreateBusFromInMemoryAudioFile() now honors the documented sample_rate == 0.0f contract by decoding at the file's native rate instead of passing 0.0f into TryCreateBySampleRateConverting() (which previously divided by zero and returned a 0-frame bus). TryCreateBySampleRateConverting() now validates the target rate and returns nullptr for invalid/negative values. Alongside this, blink::WebAudioBus::ChannelData() changed from float* ChannelData(unsigned) to base::span<float> (with CHECK_LT bounds enforcement) — a source-level signature change in a Blink public platform header, though a mechanical span migration. (d2aed4c)
    MediaBlink
  • Rust demuxer metadata parsing enabled: turns on symphonia's all-meta feature so container readers (MP3/ID3v2) parse embedded metadata tags during probing and demuxing; only generated BUILD.gn feature flags change. Separately, Media Router upgraded remaining Remote Playback codec DCHECKs in MediaRouterUI/MediaRouteStarter to CHECK, enforcing the existing MediaNotificationService codec-filter precondition (crash instead of silent bad state on violated invariants). (592e07e) (2144f13)
    MediaBrowser

Browser Lifecycle & Performance

  • Discarded-frame Stage 2 shutdown now ignores workers: RenderFrameHostImpl::DiscardFrame()'s reply callback passes ignore_workers=true to FastShutdownIfPossible(), matching DiscardedRFHProcessHelper::ShutdownIfPossible(), so a discarded renderer holding worker refs can still be reclaimed. Tests were moved from IncrementWorkerRefCount() to IncrementPendingReuseRefCount(), MockRenderProcessHost::FastShutdownIfPossible() now respects ignore_workers, and FastShutdownExitObserver was refactored onto base::ScopedObservation. (2c4a157)
    PerformanceBrowserTesting

Autofill & Payments

  • IBAN form-detection patterns rolled and corrected: rolls components/autofill/.../internal_resources to pick up new IT/FR/ES/PL IBAN_VALUE patterns (only consumed by enable_src_internal Google Chrome builds, gated by AutofillEnableExpandIbanRegexPattern), and fixes the legacy Spanish pattern which matched plural "número de cuentas" and missed the common singular "Número de cuenta". Expect improved IBAN field classification on localized forms. (873d043)
    AutofillPayments

Web Platform APIs (Experimental) & Build Flags

  • Experimental SmartCardContext.release(): adds the Blink IDL binding plus a use counter behind the new SmartCardContextRelease runtime-enabled feature and matching chrome://flags entry. The method is a stub that always rejects with NotSupportedError until the implementation lands; no stable-surface change. (bd0c800) (ce6c06c)
    BlinkSecurityBuild
  • ENABLE_SMART_CARD raw define converted to a buildflag in //third_party/blink/public:buildflags (BUILDFLAG(ENABLE_SMART_CARD)), with consumers in //content/browser DevTools and isolated-web-app entitlement tests migrated. Fixes the define never reaching isolated_web_app_entitlements_browsertest.cc; out-of-tree build files still using #ifdef ENABLE_SMART_CARD will silently compile the code out. (c61e200)
    BuildBlinkSecurity

Testing & Infrastructure

(b40840e) (445ead6)
    TestingInfra
  • Android browser-test runtime trimming: adds android.phone.android_browsertests.filter excluding the two tablet-only side-panel suites on phone CQ/CI builders (removing ~95 no-op Activity launches), and aligns AndroidBrowserTest with InProcessBrowserTest by disabling search preconnect/prewarm, kRestartNetworkServiceUnsandboxedForFailedLaunch, kTransientKeepAlivePolicy, and IPH features by default. Test-only behavior; embedded test harnesses relying on those defaults must enable them explicitly. (5009d53) (231082c)

Blink Rendering Fixes (informational)

Also, the GC-deferred CalculationValue handle-decrement change in ~Length() was reverted after a crash regression, restoring the original length.cc behavior. (c71b0c8) (600f90b)
