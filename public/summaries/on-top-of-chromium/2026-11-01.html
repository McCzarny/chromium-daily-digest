Chromium Digest: 2026-11-01

Overview

Analyzed 36 commits from the Chromium main branch (2026-11-01), ranging from (df60081) to (d21d301). After filtering out test re-enables, protobuf roll-script plumbing, translation XTBs, histogram metadata, OWNERS updates, and other mechanical or platform-specific work, a much smaller set of consequential changes remains: a macOS File System Access symlink hardening fix, browser-UI changes in Send Tab to Self and Reading List context menus, color/theme versioning behavior, enterprise reporting debug surfaced in chrome://connectors-internals, new Cronet kill-switch HTTP flags, and performance/DevTools-affecting Blink and compositor changes. No commits in this batch remove stable, embedder-facing public APIs or change stable public signatures, so there are no confirmed major breaking changes.

Security & File System Access

  • macOS File System Access symlink hardening: CreateClonedSwapFile() in FileSystemAccessFileHandleImpl now calls base::IsLink() on both the source and the candidate <name>.crswap swap path before invoking clonefile(). Because LocalFileUtil::GetLocalFilePath() reports existing symlinks as FILE_ERROR_NOT_FOUND, a dangling .crswap symlink could be followed as the clone destination (or a source path swapped for a symlink could redirect the read). Symlinked sources now return FILE_ERROR_NOT_FOUND; symlinked swap candidates return FILE_ERROR_EXISTS so DidCloneSwapFile() advances to the next unused filename. Behavior for createWritable({keepExistingData: true}) changes only in the presence of symlinks — treat it as a security fix, not a breaking API change. (8fa41a1)

Browser UI

  • Send Tab to Self UI handler rename: SendTabToSelfToolbarIconController is renamed to SendTabToSelfReceivingUiHandler (files moved under chrome/browser/ui/send_tab_to_self/) since the toolbar icon and bubble have been removed. DismissEntries is now a no-op, CanShowOnBrowser moved into an anonymous namespace, and unused includes/BUILD.gn deps were dropped. This only affects internal Chrome layers; components/send_tab_to_self/receiving_ui_handler.h remains the embedder-facing abstraction. (a1e1467)
    BrowserUISync
  • Reading List context menu validates URL support: RenderViewContextMenu now checks that the ReadingListModel is loaded and SupportsCurrentUrl() before appending, enabling, or executing the "Add Link to Reading List" item. Previously any valid link URL (including mailto: and javascript:) could be added, which later crashed ClientTagBasedDataTypeProcessor::Put during sync because ReadingListEntry only supports HTTP/HTTPS. This is a user-visible behavior fix (item hidden for unsupported schemes), not a public API break. (653d7ca)
    BrowserUISync
  • Color provider API and web theme version sync: ColorProviderManager::GetColorProviderFor() now takes ColorProviderKey by const& instead of by value, eliminating a copy and custom-theme refcount churn on cache hits. NativeTheme additionally increments associated_web_instance_'s system_color_version() in SetAssociatedWebInstance() and NotifyOnNativeThemeUpdatedImpl() when kThemeChangeOptimization is enabled, so web-process color caches are invalidated consistently. Signature change is source-compatible at call sites; not a breaking change per scope rules. (f7bea1a)
    UIThemesPerformance

Enterprise Reporting

  • chrome://connectors-internals shows the last uploaded signals report: ReportScheduler now caches a human-readable JSON copy of the security signals embedded in a profile report (pending_signals_json_ → last_uploaded_signals_json_ on successful upload, cleared in Stop() only when security reports are disabled), exposed through a new GetLastUploadedSignalsJson() accessor. GetSecuritySignalsInReport() gained an include_policy_summary = false defaulted parameter, and the mojom ConnectorsInternalsHandler gained a SignalsSource distinction (kLastUploadedReport vs kCollectedOnDemand) so the page no longer misleadingly reports certificates_count: 0. ReportGenerationConfig::ToString() now multi-line pretty-prints selectors. All defaulted/added API surface — no existing callers break. (e2bea00)
    EnterprisePolicySecurity

Networking & Cronet

  • Three Cronet kill-switch HTTP flags added: Cronet_disable_set_idempotency makes ExperimentalUrlRequest.Builder#setIdempotency a silent no-op (request keeps DEFAULT_IDEMPOTENCY); Cronet_disable_shared_brotli makes UrlRequest.Builder#setRawCompressionDictionary a no-op including skipping argument validation; Cronet_disable_nqe prevents NQE from being enabled in the native URLRequestContextConfig and turns all NQE accessors/listeners (getEffectiveConnectionType, getHttpRttMs, getTransportRttMs, getDownstreamThroughputKbps, configureNetworkQualityEstimatorForTesting, addRttListener, addThroughputListener, etc.) into no-ops or unknown-metric returns instead of throwing IllegalStateException. These are opt-in flags (default off), so behavior is unchanged unless explicitly enabled — flag additions are explicitly out of breaking-change scope. Cronet is Android-centric and thereby outside the Windows/macOS focus, but the flags affect the shared networking stack. (1599545) (2d864f5) (ebd5dfe)
    NetworkAndroid
  • Glic MES prewarming credential mode behind a flag: ContextualCueingService currently prewarms the Model Execution Service connection with allow_credentials=true, but ModelExecutionFetcherImpl omits credentials, so the preconnected socket lands in a different ClientSocketPool::GroupId (net::PrivacyMode) partition and is never reused. A new kGlicZeroStateSuggestionsPreconnectWithoutCredentials feature (disabled by default) experiments with allow_credentials=false. Nothing changes without the flag. (d21d301)

Performance, DevTools & Platform Internals

  • **Performance.getEntries* marked [Affects=Nothing]**: performance.getEntries(), getEntriesByType(), and getEntriesByName() in performance.idl are now annotated [Affects=Nothing]. Previously, throwOnSideEffect: true evaluations (DevTools Console eager evaluation and the AI executeJavaScript tool) aborted with EvalError: Possible side-effect in debug-evaluate on these pure readers of buffered PerformanceEntry records. This is an added annotation, not a removal or signature change. (3cbf602)
    BlinkDevToolsPerformance
  • Lock-free scroll timing shared buffer: cc/metrics/scroll_timing_buffer replaces the single 32-byte atomic_ref<ScrollTimingInfo> with per-field SharedAtomic values, guaranteeing lock-free access at compile time and avoiding process-local locking fallbacks while preserving the existing seqlock ordering/overwrite detection. Explicit padding and whole-record shared-memory assertions are removed, and Push() destructures the record so new fields must update the transport. Internal layout change only — no API surface affected. (3cad633)
    CompositorPerformance

This deletes exported Blink platform symbols, but since nothing in the tree (including embedders) calls them it is an internal cleanup rather than a stable public API removal. (2dd5624)
