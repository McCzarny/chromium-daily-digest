Chromium Digest: 2026-09-27

Overview

This digest analyzes **37 commits** landed on this day, ranging from (1498cf2) down to (0784c35). After filtering out changes outside the desktop-browser scope (Blink/V8 webpage processing such as EditContext, WebMCP, WebCodecs and UserAgentData, plus Android, iOS, ChromeOS/Ash, and tvOS-specific work), **26 commits** remain relevant for projects built on top of Chromium targeting Windows and macOS. Two commits — the omnibox enum-class modernizations — are **confirmed MAJOR breaking changes** to stable APIs that embedder code compiles against. The rest consists of internal TabFeatures refactoring, Safe Browsing build-mode scoping, a series of AV1 encoder bitstream correctness fixes, macOS accessibility corrections, and stability/bug fixes.

Omnibox API Modernization (⚠ Breaking)

  • ⚠️BREAKING: AutocompleteProvider::Type was converted from a legacy unscoped C-style enum into a scoped enum class. All enumerators were renamed (TYPE_SEARCH → Type::kSearch, TYPE_DOCUMENT → Type::kDocument, TYPE_UNSCOPED_EXTENSION → Type::kUnscopedExtension, etc.) and implicit conversion to int was removed, so embedder code doing bitmask math on provider types (e.g., AutocompleteControllerConfig.provider_types) must now use explicit static_cast<int>(...). The change touched 72 files across components/omnibox/browser, chrome/browser/ui/omnibox, Ash app-list integration, and the extensions omnibox API tests. Any embedder referencing the old TYPE_* constants will fail to compile. (1d9bb5a)
    BrowserUIExtensions
  • ⚠️BREAKING: AutocompleteMatchType was converted to a scoped enum class in the omnibox namespace. AutocompleteMatch::type and related signatures changed (e.g., AutocompleteMatchType::Type match_type → omnibox::AutocompleteMatchType match_type), and all enumerators were renamed (CALCULATOR → kCalculator, SEARCH_WHAT_YOU_TYPED → kSearchWhatYouTyped, CLIPBOARD_URL → kClipboardUrl, etc.). With 205 files modified, this is the widest-reaching change of the day; embedders constructing or inspecting AutocompleteMatch objects must migrate to the new scoped enumerators. (ceb5b20)
    BrowserUI

Browser Architecture: TabFeatures Migration

  • A series of agent-generated CLs continues the migration of tab helpers off WebContentsUserData and into TabFeatures/TabFeaturesAndroid. Migrated this day: TailoredSecurityUrlObserver (safe browsing), SiteProtectionMetricsObserver, NavigationMetricsRecorder, NavigationPredictorPreconnectClient, NoStatePrefetchTabHelper, and ExternalProtocolObserver. Each lost its WebContentsUserData inheritance and FromWebContents() access (none had external callers), and instantiation moved from TabHelpers::AttachTabHelpers into TabFeatures on desktop and Android. This is internal refactoring — embedders relying on AttachTabHelpers see no API change. (636c3b1) (1d5918e) (70f4169) (59da456) (019110a) (30fa524)

Security & Safe Browsing

  • Two CLs continue reviving builds with safe_browsing_mode=0 by scoping Safe Browsing code behind build flags. Generic HTTPS/security-state/Page Info/site-protection/search-engine-settings coverage stays available in mode 0, while password-protection and hijacking-detection paths requiring Safe Browsing services are guarded. Cloud binary upload support is retained for enterprise content analysis in mode 0 (now using the profile URL loader instead of the global Safe Browsing service), and suspicious-site UI, redirect attribution, and download-protection coverage are scoped to builds that provide their implementations. Relevant for embedders building Chromium without Safe Browsing services. (dd5257a) (201fde4)
    SecurityBuildEnterprise
  • Behavioral change (policy/enterprise): FmRegistrationTokenUploader now starts its InvalidationListener only once the CloudPolicyClient is connected (or immediately if already connected), instead of in the constructor. Previously, every desktop profile — including unmanaged and fresh signed-out ones — checked in with android.clients.google.com and registered FCM tokens at every startup that were never uploaded. Unmanaged profiles no longer register with FCM, reducing unwanted network traffic and check-ins. (89cf896)

Stability & Bug Fixes

  • Fixed a NOTREACHED crash in ThumbnailSchedulerImpl::Schedule(). ThumbnailReadinessTracker now remains in Readiness::kNotReady while a WebContents is discarded, so the empty-document load from FrameTree::Discard() no longer transitions readiness to kReadyForFinalCapture. This prevents hovering a discarded tab from requesting capture, which inadvertently triggered a reload navigation and a synchronous re-entrant SetTabCapturePriority(kNone) call. The scheduler is also hardened against state corruption: capture-priority is reset to kNone in RemoveTab() before erasing the TabNode. (4ac0142)
    BrowserUITabs
  • Fixed an in-the-wild renderer kill ([Renderer kill 123] Prefetch/IsValidCrossOrigin: frame origin mismatch) in browser-side handling of <link rel="prefetch">. Because SubresourceProxyingURLLoaderService binds a standalone, non-frame-associated URLLoaderFactory pipe during CommitNavigation(), request_initiator could legitimately differ from the frame's last-committed origin. The fix tracks did_commit_navigation in BindContext, aborts stale-initiator requests with net::ERR_ABORTED, returns net::ERR_INVALID_ARGUMENT on origin mismatch without calling ReportBadMessage(), and defers EnsureCrossOriginFactory() until after origin validation succeeds. (ef7e3ce)
    NetworkNavigationSecurity
  • Reland of the fix for the bookmark manager not opening redirected URLs. After the bookmark-model migration to UUIDs, redirect lookups by legacy numeric IDs failed; a new helper maps legacy IDs to the new UUIDs. The reland replaces a real-browser test setup (which had timing issues causing WPT failures) with a faked browser instance. Changes are in chrome/browser/resources/bookmarks/router.ts and util.ts (WebUI TypeScript). (60fdad7)

Explicitly no change in behavior or functionality; the removed accessor is a minor internal Views metric, not a stable embedder surface. (c0bd9d7)
    UI
  • The kDefaultBrowserStickyModal field-trial flag is now only queried when the prompt-surface parameter actually selects a modal dialog, instead of unconditionally (which previously activated the trial for all clients). IsDefaultBrowserPromptSurfacesEnabled() no longer checks the sticky-modal flag, the DefaultBrowserModalUI WebUI binder is gated on the raw prompt-surface param, and DefaultBrowserSurfaceManager::Show() uses the entrypoint type so non-modal surfaces never query the flag. Affects default-browser prompt behavior on desktop. (aff6af0)

Accessibility (macOS)

  • Focusable unnamed lists no longer expose their content-derived name as AXTitle on macOS. Previously VoiceOver announced the text of every item when the list received Tab focus; it now announces only the list role and item count, matching Safari/WebKit behavior. Individual items remain available when navigating inside the list. Expected-output accessibility test data updated accordingly. (f1699d6)
    AccessibilitymacOS
  • Fixed VoiceOver announcing the second and subsequent column headers of a table twice. Chromium on macOS included the current column header in its own AXColumnHeaderUIElements relationship; the current header is now excluded when collecting column headers, matching WebKit. Affects ui/accessibility/platform/ax_platform_node_cocoa.mm and macOS accessibility test expectations. (72aefe3)
    AccessibilitymacOS

Media: AV1 Encoder Bitstream Correctness

  • A six-commit series fixes AV1 bitstream writing in media/gpu/av1_builder.cc, where missing or extra syntax elements desynchronized every subsequent header field. Fixes include: writing allow_warped_motion on inter frames and skip_mode_present when the reference structure allows it; inferring error_resilient_mode, refresh_frame_flags, and frame_size_override_flag per frame type and gating use_ref_frame_mvs/primary_ref_frame/reference_select/global motion correctly; gating loop filter, CDEF, and tx mode on CodedLossless (and loop restoration on AllLossless) — reachable from WebCodecs with a quantizer of 0; moving separate_uv_delta_q into the sequence header; and terminating fixed-size leb128 padding. A fuzzer (av1_builder_fuzzer) and D3D12 encode delegate tests were updated. (380c6e4) (a33531d) (99868f2) (0046509) (15fd67d) (5a7d254)
