Chromium Digest: 2026-11-17

Overview

Chromium main received 1,141 commits on 2026-11-17, about 952 of which touched areas relevant to Windows/macOS embedders (browser UI, extensions, networking, security, base/ui/testing infrastructure). The day contains two genuine breaks to stable public APIs: the removal of the size_t-based base::DiscardableMemoryAllocator interface and the removal of ContentBrowserClient::ShouldTryToUseExistingProcessHost(). Beyond those, the batch is dominated by enterprise capture protection, TLS client-certificate hardening, a macOS H.265 alpha-decoding out-of-bounds fix, Secure DNS flag removal, extension API additions (autofillPrivate Wallet offers, captureVisibleTab in standalone windows), and build/toolchain events (Bedrock test_support dep removal, libc++ roll, macOS Aperitif helper bundle consolidation) that carry downstream build and packaging risk. First commit: (ec5ac9a); last commit: (d99aa82).

Breaking API Changes

  • ⚠️size_t-based base::DiscardableMemoryAllocator API removed from the BASE_EXPORT interface: AllocateLockedDiscardableMemory(size_t), AllocateLockedDiscardableMemoryWithRetryOrDie(size_t, OnceClosure), GetBytesAllocated() and ClientDiscardableSharedMemoryManager::SetBytesAllocatedLimitForTesting() are deleted, while the base::ByteSize overloads and GetAllocatedSize() become pure virtual. Any embedder subclass overriding the old virtuals or calling the removed overloads fails to compile and must migrate to base::ByteSize. Follow-ups are test-only migrations. (f07f943)
    BaseStorage
  • ⚠️ContentBrowserClient::ShouldTryToUseExistingProcessHost() removed. The virtual hook and all in-tree overrides (including ChromeContentBrowserClient) are deleted; its WebUI process-lock logic (WebUIConfigMap::GetProcessLockHost(url)) is now inlined into RenderProcessHostImpl::GetProcessHostForSiteInstance(), keyed on site_info.site_url(). Out-of-tree embedders overriding the hook no longer compile, and those relying on it to steer renderer-process reuse silently lose that control — any WebUI declaring a process-lock host now reuses an existing renderer process unconditionally. (d4c9d38)
    BrowserNavigation

Security & Privacy

  • Tab Share Protection now blocks a browser from capturing its own protected windows via getDisplayMedia(); OS-level screenshot exclusion previously did not stop self-capture of windows marked under ENTERPRISE_SCREENSHOT_PROTECTION. views::Widget gains an additive RegisterAllowScreenshotsChangedCallback(), and new public helpers GetWidgetFromWindowId() / IsWindowSharingBlockedByDataProtection() in desktop_capture_devices_util.h let custom pickers honor admin blocks; blocked sources render as "Blocked by your admin" instead of a thumbnail. (73689a6) (40b117b)
    SecurityEnterpriseMedia
  • TLS client-certificate hardening against buggy key providers. SSLClientSocketImpl now rejects Sign() returning OK with a 0-byte signature and an empty GetAlgorithmPreferences() locally (ERR_SSL_CLIENT_AUTH_SIGNATURE_FAILED, ERR_SSL_CLIENT_AUTH_NO_COMMON_ALGORITHMS), evicting the broken key from SSLClientAuthCache so the normal stale-key retry runs instead of sending an invalid CertificateVerify or falling back to BoringSSL's default algorithm list. Directly relevant to embedders shipping PKCS#11/CNG/CryptoTokenKit keys; new Net.SSLClientCertSignResult histograms and NetLog fields. (2895bec)
    NetworkSSLSecurity
  • H.265 auxiliary alpha-layer validation; HEVC alpha disabled in WebCodecs on macOS. Alpha-layer SPS/PPS/slice NALUs were forwarded to the accelerator unvalidated, and on Apple Silicon VideoToolbox the IOSurface is sized from the base-layer description while layer-1 dimensions write plane 2 — an out-of-bounds write. The decoder now compares base-vs-alpha configs and double-checks slices in VideoToolboxH265Accelerator::SubmitSlice(); VideoDecoderConfig::AlphaMode is plumbed in, so HEVC alpha is opaque in WebCodecs but preserved for <video>. (ab36475)
    MediaGPUmacOS
  • File System Access downgrades a hand-edited user ALLOW to ASK. GetReadGuardContentSetting()/GetWriteGuardContentSetting() route through a new GetGuardContentSetting() that returns CONTENT_SETTING_ASK when the value is ALLOW from SettingSource::kUser (Chrome UI and policy only ever write ASK/BLOCK), and a new CanRequestObjectPermission() override applies the same downgrade to ObjectPermissionContextBase grant paths. Persisted grants remain visible for ASK origins. (4ba5176)
    SecurityStorage
  • ORB kSniffMore bypass closed in Web Bundles. WebBundleURLLoaderFactory::SendResponseToLoader previously fell through orb::ResponseAnalyzer::Init's kSniffMore decision to kAllow, delivering inner responses without payload inspection. It now reads up to net::kMaxBytesToSniff from the bundle and evaluates via Sniff/HandleEndOfSniffableResponseBody, with pending reads aborted on error or destruction. (cdc4c4d)

Networking

  • Secure DNS bundled-settings flag removed and DoH fallback semantics pinned. kBundledSecuritySettingsSecureDnsV2 (expired in M150) is deleted along with its chrome://flags entry and metadata; StubResolverConfigReader::ShouldUseDohFallback() now returns false without consulting Safe Browsing (the //chrome/browser/net Safe Browsing dep is dropped), kDnsOverHttpsAutomaticModeFallbackToDoh is removed from the chrome.settingsPrivate allowlist, and GeneratedSecuritySettingsBundlePref writes only the profile-level bundle pref so local-state DoH preferences are no longer overwritten.   • HostCache capacity is now scoped per NetworkAnonymizationKey. max_entries applies per NAK inside an outer LRU of up to 32 active partitions (mirroring ConnectPredictorLRUCache and the CORS preflight cache), and HostCache::size() is added. Flooding the cache under a single origin can no longer evict other sites' entries, keeping DNS hit rates stable under hostile single-origin load. (c2a5dc3)

(58ff72c)
